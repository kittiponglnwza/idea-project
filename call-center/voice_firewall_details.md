# โครงการ: VoiceGuard 2.0 (โหมดคุ้มครองสายสนทนา)
**AI ผู้ช่วยส่วนตัวระหว่างการโทร (AI Assistant during a call)**

---

## 1. การปรับสถาปัตยกรรม (The Pivot)
เพื่อแก้ปัญหาข้อจำกัดด้าน OS (Android/iOS API) เราเปลี่ยนจาก "แอปดักฟังเบื้องหลัง" เป็น **"โหมดคุ้มครองสายสนทนา (Protected Call Mode)"** ซึ่งทำงานภายใต้สิทธิ์ที่ระบบปฏิบัติการอนุญาตอย่างถูกต้อง

### กลไกการทำงานใหม่:
1. **ขอสิทธิ์ Default Dialer (เฉพาะ Android):** แอปเราจะทำงานเป็นแอปโทรศัพท์หลัก (Default Phone App) ซึ่ง Android อนุญาต ทำให้เรามีสิทธิ์กดรับสาย ตัดสาย และดูเบอร์โทรเข้าได้
2. **การดึงข้อมูลเสียง/ข้อความ (Data Extraction):** 
   - *วิธีที่ 1 (สาย Hardcore):* ใช้ **Accessibility Service** อ่านข้อความจากฟีเจอร์ **Live Caption** ของระบบ (Google มีฟีเจอร์แปลงเสียงเป็น Text สดๆ เราแค่จับ Text นั้นมาวิเคราะห์ต่อ) **ไม่ต้องดักฟังเสียงเอง!**
   - *วิธีที่ 2 (สาย UX):* เมื่อเจอเบอร์แปลก แอปจะรับสายในโหมด **Speakerphone อัตโนมัติ** และเปิดไมค์เครื่องเพื่อฟังเสียงสนทนาภายนอก (หลีกเลี่ยงการขอสิทธิ์ดัก Audio Stream ภายในเครื่อง)
3. **การแจ้งเตือน (Intervention):** ไม่ใช้การแทรกเสียง (Audio Inject) แต่ใช้ **Haptic Feedback (สั่นเตือนแรงๆ)** และ **หน้าจอเปลี่ยนเป็นสีแดงกะพริบ** พร้อมข้อความใหญ่ๆ ว่า "โอกาสหลอกลวง 95% วางสายเดี๋ยวนี้!" 
4. **หากผู้ใช้ไม่วางสาย:** แอปที่มีสิทธิ์ Default Dialer สามารถสั่ง End Call ได้เพื่อความปลอดภัยขั้นสุด

---

## 2. ฟีเจอร์ที่ปรับให้ทำได้จริง (Feasible Features)

*   **เน้น NLP, ตัดการวิเคราะห์ความเครียด (AER) ทิ้ง:** เพื่อลดคำถามเรื่องความแม่นยำของโมเดล เราจะโฟกัสที่ **Intent Classification** (การวิเคราะห์เจตนาจากข้อความ) เท่านั้น ซึ่งแม่นยำและอธิบายหลักการทำงานได้ง่ายกว่า
*   **Dynamic Knowledge Base:** โมเดล NLP จะไม่จำแค่ Keyword (พัสดุ, ตำรวจ) แต่จะเชื่อมกับ **RAG (Retrieval-Augmented Generation)** ดึงข่าวสแกมล่าสุดจากเว็บตำรวจไซเบอร์มาอัปเดตเป็น Context ให้ AI ทุกวัน โจรเปลี่ยนมุก AI ก็รู้ทัน

## 3. สิ่งที่นำไปโชว์กรรมการ (The Wow Demo)
*   นำมือถือ Android ที่ติดตั้ง VoiceGuard 2.0 ขึ้นเวที
*   ให้เพื่อนโทรเข้าเครื่องด้วยเบอร์แปลก
*   แอปเด้งถามผู้ใช้: "เบอร์แปลก - รับสายใน Protected Mode หรือไม่?"
*   พอกดรับ ระบบเปิด Live Caption เบื้องหลัง + วิเคราะห์ข้อความแบบ Real-time บนหน้าจอ
*   เพื่อนพูดบท: *"คุณมีคดีฟอกเงิน ค้างชำระบัตรเครดิต..."*
*   หน้าจอมือถือสั่นแรง กะพริบสีแดง และ **ตัดสายทิ้งอัตโนมัติ** ภายใน 5 วินาที
*   พร้อมเด้งหน้าจอ Micro-Learning: *"ทำไมเราถึงตัดสายนี้? เพราะตำรวจไม่มีนโยบายทวงหนี้ผ่านโทรศัพท์"*

## 4. Q&A เตรียมตอบกรรมการสาย Tech (Defense Section)

**Q1: ใช้ API ไหนในการดักฟังเสียง? ระบบอนุญาตเหรอ?**
> **A:** เราไม่ได้ดักฟัง Audio Stream โดยตรงครับ เราใช้ 2 ทางเลือก: 1) ทำงานเป็น Default Dialer ควบคู่กับการใช้ Accessibility Service ดึงข้อความจาก Live Caption ของระบบ (Text-only) หรือ 2) บังคับเปิด Speakerphone และใช้ Microphone ปกติของเครื่องฟังเสียงสนทนาภายนอก ซึ่งเป็น API พื้นฐานที่แอปทั่วไปขอสิทธิ์ได้ครับ

**Q2: โจรเปลี่ยนสคริปต์ทุกวัน AI จะตามทันไหม?**
> **A:** โมเดลเราไม่ได้จำ Keyword (Rule-based) แต่ใช้ Semantic Analysis ครับ เราใช้เทคนิค RAG (Retrieval-Augmented Generation) อัปเดต Database ข่าวหลอกลวงรายวันเข้าไป โจรจะอ้างเป็นตำรวจ ธนาคาร หรือการไฟฟ้า AI จะจับที่ "เจตนา (Intent)" เช่น การสร้างความกลัว การเร่งให้โอนเงิน หรือการขอข้อมูลส่วนตัว ซึ่งเป็นแก่นที่ไม่เคยเปลี่ยนครับ

**Q3: ความแม่นยำ (Accuracy) เท่าไร? มี False Positive ไหม?**
> **A:** เราคาดหวัง Precision ที่สูงมาก (>95%) เพราะเราออกแบบให้ระบบทำงานต่อเมื่อ "ระดับความเสี่ยงถึงขีดสุด (High Confidence)" เท่านั้น หาก AI ไม่แน่ใจ (เช่น 50-80%) ระบบจะไม่ตัดสาย แต่จะขึ้นแค่ **ป้ายเตือนสีเหลือง** ให้ผู้ใช้ตัดสินใจเอง เพื่อป้องกัน False Positive ที่ไปตัดสายสำคัญของครอบครัว

**Q4: แล้วเรื่อง PDPA ล่ะ? เก็บข้อมูลโทรศัพท์แม่ผมไปไหนบ้าง?**
> **A:** Privacy-by-design ครับ ระบบวิเคราะห์ข้อความทั้งหมดเกิดขึ้น **On-device (บนมือถือ)** ข้อมูลที่ถูกส่งขึ้น Cloud มีเพียงแค่ "Log การบล็อกสาย" (เช่น เบอร์โทรอะไร, ถูกบล็อกเวลาไหน, จับ Intent หมวดหมู่ไหนได้) ซึ่งข้อมูลนี้จะถูกส่งไปที่เครื่องของบุตรหลาน และส่งเข้า Database กลางแบบ Anonymous เพื่ออัปเดตโมเดลป้องกันภัยให้คนอื่นๆ ครับ ไม่มีการเก็บไฟล์เสียงแน่นอน

**Q5: iPhone ใช้ได้ไหม?**
> **A:** สำหรับเฟสแรกและ MVP เราโฟกัสที่ Android ก่อนครับ เพราะ API ยืดหยุ่นกว่าและเป็นกลุ่มผู้ใช้งานที่ถูกหลอกเยอะที่สุดในไทย ส่วน iOS จะอยู่ใน Roadmap ถัดไป โดยอาจปรับรูปแบบเป็น การแคปเจอร์หน้าจอแชท (Screenshot Analysis) แทนการดักฟังสายเรียกเข้าครับ

**Q6: ถ้า AI ตัดสายผิด (เช่น ตำรวจโทรมาจริง) ใครรับผิดชอบ?**
> **A:** จุดประสงค์ของเราคือ "ชะลอการตัดสินใจ" ครับ แม้ระบบจะตัดสายผิด แต่เบอร์นั้นจะยังอยู่ในประวัติการโทร ผู้ใช้สามารถตรวจสอบกับลูกหลานหรือโทรกลับได้เสมอ การตัดสายผิดมีต้นทุนแค่ "ความรำคาญและโทรกลับใหม่" แต่การไม่ตัดสายมีต้นทุนคือ "เงินเก็บทั้งชีวิต" ครับ
